# ZOR (Zones Of Rift) — المخطط التقني

> الاسم مؤقت (ZOR = Zones Of Rift، «مناطق الصدع»). يوجد على ستيم لعبة بطاقات باسم ZOR: Pilgrimage of the Slorfs، فلا يُعتمد للنشر قبل فحص العلامة التجارية رسميًا.

> نموذج أولي قابل للعب. كل الأرقام أدناه **قيم افتراضية قابلة للتعديل** من `core/config.js` و `core/data.js`، وليست قواعد نهائية.
> كل العوالم والشخصيات أصلية ومؤقتة للتجربة.

---

## 1. بنية اللعبة

اللعبة ويب خالص (HTML/CSS/JS بدون مكتبات ولا خطوة بناء)، تعمل بفتح `index.html` مباشرة أو عبر أي خادم ملفات ثابتة.

```
multiverse-battler/
├── index.html            هيكل الشاشات
├── core/                 منطق اللعبة — لا يعرف شيئًا عن الواجهة
│   ├── config.js         كل أرقام التوازن والإيقاع والاقتصاد
│   ├── data.js           العوالم، الأدوار، الوحدات، الأبطال، المعدات، التعاويذ، التآزر
│   ├── util.js           مولد أرقام عشوائية ببذرة (seed) — النتائج قابلة للإعادة
│   ├── synergy.js        حساب التآزر النشط (دالة نقية)
│   ├── combat.js         محاكاة القتال التلقائي الحتمية
│   ├── match.js          آلة حالات المباراة + المتجر + الاقتصاد + التطوير
│   ├── ai.js             خصم آلي (يستخدم نفس واجهة اللاعب البشري)
│   └── telemetry.js      بيانات التوازن (نسب الفوز والاستخدام)
├── ui/
│   ├── art.js            رسوم SVG إجرائية أصلية لكل شخصية (بدون صور خارجية)
│   ├── ui.js             الشاشات والتفاعل وتشغيل القتال
│   └── style.css
└── tools/
    ├── simulate.js       محاكي توازن: آلاف المباريات ذكاء اصطناعي ضد ذكاء اصطناعي
    └── test.js           اختبارات القواعد
```

**مبدأ أساسي:** الطبقة `core/` مستقلة تمامًا عن الواجهة. نفس كائن `Match` يقوده:
اللاعب البشري (عبر `ui.js`)، والذكاء الاصطناعي (`ai.js`)، والمحاكي (`tools/simulate.js`).
هذا يجعل إضافة اللعب عبر الشبكة لاحقًا مباشرة: الخادم يشغّل `Match` + `Combat` نفسها.

### الشاشات
القائمة الرئيسية ← اختيار النمط ← اختيار البطل ← شاشة المباراة (المتجر، الساحة، الاحتياط، لوحة التآزر، لوحة البطل والقدرات، المعدات، التحديد) ← نتيجة الجولة ← شاشة النتائج ← الإحصائيات.
بالإضافة إلى: مكتبة الشخصيات، نافذة تفاصيل الشخصية (الخصائص لكل نجمة)، شاشة التطوير، و"كيف ألعب".

### الهوية البصرية — «حبر الأبعاد» (Manga Ink)
هوية مستقلة تمامًا عن لعبة الاستوديو (التي تعتمد الكحلي الناعم والبنفسجي والزوايا الدائرية):
- **الألوان:** حبر أسود `#121010`، ورق كريمي `#f3ead6`، أحمر قرمزي `#e0262f`، ذهبي `#f2b300`. لكل عالم لونه الخاص في الشارات والإطارات.
- **الخطوط:** Lalezar للعناوين (عريض بطابع ملصقات الأنمي) و Readex Pro للنصوص.
- **الأشكال:** لوحات مانغا بحدود حبر سميكة (3px)، وزوايا مقطوعة بدل الدائرية، وظلال صلبة بلا تمويه، وأزرار مائلة.
- **الملمس:** نقاط هافتون (halftone)، وخطوط سرعة، وانفجارات شعاعية خلف العناوين ونتائج الجولات.
- **البطاقات:** على شكل بطاقات تداول: شريط لون الفئة في الأعلى، والتكلفة في ختم أسود، وشارة العالم.
- **الساحة:** حلبة حبر داكنة داخل إطار ورقي بظل أحمر، وخط الصدع متقطع أحمر.
- **الصور الشخصية:** إطارات لوحات مانغا (مثمن للأبطال) مع هافتون وحدود حبر، مولّدة بـ SVG.
- **المؤثرات:** أرقام ضرر بخط Lalezar محددة بالحبر، ولافتات "ضربة" مائلة للقدرات والأحداث الكبرى.

### شخصيات الأبطال
أربعة أبطال أصليين برسم من صور المستخدم (مولّدة بالذكاء الاصطناعي)، ولكل واحد شخصية تناسب صورته (الأرقام والقدرات لم تتغير):
- **كيرو — الجمر الهادئ (الجمر):** هادئ ومحسوب من الخارج، ينفجر عند الهجوم. قدراته: أمر الهجوم، نيزك الجمر.
- **ميران — حارس المدّ الصامت (المدّ القمري):** ظلّ هادئ يحمي الفريق بالدروع والعلاج. (المعرّف الداخلي `merin`.)
- **زيرو-كاي — الظلّ المشفّر (نيون-٩):** غامض يسبق خصمه بخطوة.
- **أوراث — الحارس المحلّل (الغابة):** هادئ وتحليلي يقرأ المعركة قبل أن تبدأ؛ خط أمامي صلب وتحكم.

### نظام البطاقات (بدون تراكب)
كل وحدة وبطل ومعدة **بطاقة** بمناطق ثابتة لا تتداخل أبدًا:
- **بطاقات بالرموز (قليل من الكتابة):** لا يبقى على البطاقة غير اسم قصير (في المتجر فقط) وأرقام. الدور = أيقونة (درع/سيف/خنجر/كرة/قوس/صليب)، العالم = شعار (لهب/هلال/برق/ورقة)، المهارة = رمز حسب نوعها (انفجار، جمجمة، قناصة، شفاء…)، الفئة = جواهر ◆ (رمادي/أزرق/ذهبي)، المعدات = رموز مع أرقام مثل ⚔ +25%. تفاصيل المهارة تظهر بزر «i».
- **الإطار يدل على النجوم:** ★ إطار حبر، ★★ إطار فضي مزدوج، ★★★ إطار ذهبي متوهج بلمعة. وبطاقات الفئة 3 في المتجر عليها لمعة.
- **بطاقة المتجر:** رأس (التكلفة + الاسم) ← الرسم وعليه شارات (العالم، الدور، المهارة، وعدد النسخ التي تملكها ×2؛ ↑ يعني ستتطور) ← شريط أرقام (صحة، جواهر الفئة، هجوم).
- **بطاقة الساحة/الاحتياط:** الرسم + أيقونة الدور + النجوم + شريط أرقام فقط، بلا أي اسم (الاسم في التلميح عند التمرير).
- **بطاقة مصغّرة** (الساحة، الاحتياط): الرسم + شريط سفلي واحد فيه الاسم والنجوم والصحة والهجوم والمعدات.
- **تخطيط بدون تمرير (لابتوب):** الساحة (4 صفوف بطاقات + خط الصدع) بجانب **عمود جانبي** فيه بطل الخصم أعلى، ثم الاحتياط وأزرار القتال، ثم بطلك أسفل. حجم البطاقة يُحسب من ارتفاع الشاشة (`--cwv` في `style.css`) فتظهر كل الساحة كاملة من 720px ارتفاعًا وما فوق. على الجوال يُرصّ العمود: بطل الخصم ← الساحة ← بطلك ← الأزرار ← الاحتياط.
- **الساحة شبكة خانات** 4×2 لكل جانب: مركز قيادة الخصم، صفه الخلفي، صفه الأمامي، خط الصدع، صفك الأمامي، صفك الخلفي، مركز قيادتك. الخانة تُظهر موضع التشكيل نفسه الذي يعرفه المحرك (`f0..f3`, `b0..b3`).
- **أثناء القتال** تبقى كل بطاقة في خانتها: الهجوم = وثبة قصيرة + خط مضيء بين البطاقتين، والصحة والمانا أشرطة على البطاقة، والمشلول رمادي، والمدرّع بإطار سماوي، والساقط رمادي بعلامة ✕. المحرك لا يزال يحسب الحركة والمدى داخليًا؛ العرض فقط ثابت.
- **الشخصيات** رسوم SVG أصلية بأسلوب أنمي (عيون كبيرة بانعكاسين، رموش، خدود، خصلات)، كل شخصية سطر واحد في `ui/characters.js`.

### إطار البطاقة (أسلوب بطاقات الألعاب الفانتازية)
تصميم أصلي يتبع أعراف ألعاب البطاقات الرقمية (لا يستخدم أصول أي لعبة بعينها):
- **لون الإطار = الفصيل:** الجمر برتقالي، المدّ القمري أزرق، نيون-٩ بنفسجي، الغابة الأزلية أخضر (المعدات رمادي، التعاويذ أحمر). **طوق الرسم** يبقى معدنًا حسب الفئة: برونزي (1)، فضي (2)، ذهبي (3) مع لمعة، وذهبي للأبطال. على الساحة يكون الطوق بلون الفصيل، والنجوم تظهر كهالة: فضية ★★ وذهبية متوهجة ★★★.
- **نافذة رسم بيضاوية** بطوق معدني، وشريط اسم ملوّن بلون العالم.
- **كريستالة التكلفة** سداسية ذهبية تتدلى من الزاوية العليا اليسرى. **قرص الهجوم** (ذهبي) أسفل اليسار و**قرص الصحة** (أحمر) أسفل اليمين، وتتحدث أرقامهما مباشرة أثناء القتال.
- بين الشريط والأقراص صف أيقونات (العالم، الدور، المهارة) وجواهر الفئة. لا نصوص أخرى.
- **بطاقة الساحة (Minion):** رسم بيضاوي + طوق + قرصان + أيقونة الدور + نجوم؛ بلا اسم ولا أي نص.
- بطاقات المعدات والتعاويذ بنفس الإطار: كريستالة تكلفة، أيقونة كبيرة، شريط اسم، ورموز الأثر.

### أنماط اللعب
| النمط | الحالة |
|---|---|
| ضد الذكاء الاصطناعي (سهل/عادي/صعب) | ✅ يعمل |
| 1 ضد 1 على نفس الجهاز (تناوب على التجهيز + شاشة تسليم) | ✅ يعمل |
| مباراة ودية (مؤقت مضاعف، لا تُسجَّل) | ✅ يعمل |
| تحديات ومراحل | 🔜 البنية جاهزة: تشكيلات خصم مُعدّة مسبقًا تُمرَّر إلى `Match` |
| تصنيف تنافسي ومواسم / شبكة | 🔜 القتال حتمي ببذرة ⇒ يمكن للخادم إعادة تشغيله والتحقق منه |

## 2. مراحل المباراة

كل جولة:
1. **الموارد** — دخل ذهب، +2 خبرة، +2 جوهر، تحديث المتجر (إلا إذا كان مقفلًا).
2. **الشراء والتطوير** — شراء وحدات/معدات/تعاويذ، تحديث، شراء خبرة، الدمج التلقائي.
3. **الترتيب والقدرات** — مواقع الوحدات (أمامي/خلفي)، استدعاء البطل أو إبقاؤه، تجهيز قدرات البطل ووقت تفعيلها، تجهيز التعاويذ.
4. **القتال التلقائي** — بدون أي تحكم يدوي.
5. **النتائج** — ضرر الأبطال، السلاسل، الانتقال للجولة التالية.

المرحلتان 2 و3 تتشاركان **مؤقت التجهيز** (30 ث ضد الذكاء الاصطناعي، 35 ث لكل لاعب في نفس الجهاز). زر "جاهز" ينهيها مبكرًا. عند انتهاء الوقت تُملأ الساحة تلقائيًا من الاحتياط.

**عدالة المخزون المشترك:** من يتسوق أولًا يتبدل كل جولة.

### المراحل والجولة الأخيرة (٧ جولات)
المباراة **٧ جولات في ٤ مراحل** (`match.stages` في `config.js`):

| المرحلة | الجولات | مكافأة بعدها |
|---|---|---|
| ١ الشرارة | 1–2 | ✅ |
| ٢ الاشتعال | 3–4 | ✅ |
| ٣ الصدع | 5–6 | ✅ |
| ٤ الحسم | 7 | — (النهاية) |

- **جولة الحسم:** ارتداد الخسارة يتضاعف ×1.5 (`finaleLossMult`).
- **النهاية:** إذا سقط بطل قبلها يخسر فورًا؛ وإلا بعد الجولة 7 يفوز **الأعلى حياة**، وعند التساوي من فاز بجولات أكثر، وإلا تعادل. إن سقط البطلان في جولة واحدة يفوز من فاز بتلك الجولة.
- **الغضب داخل القتال** بقي: الضرر يتصاعد بعد 18 ث، وحد القتال 30 ث ⇒ تعادل.
- **انهيار الصدع** القديم أُلغي (`collapseStartRound: 99`)؛ الجولات المحدودة تغني عنه.

### مكافآت المراحل (اختيار واحدة من ثلاث)
بعد الجولة 2 و4 و6 يختار كل لاعب **مكافأة واحدة من 3** (دائمًا بينها وحدة مجانية). يتأخر عن خصمه بـ20 حياة أو أكثر ⇒ **خيار رابع**. الخصم الآلي يختار بنفسه حسب حالته.

| المكافأة | الأثر (المرحلة 1 / 2 / 3) |
|---|---|
| مجنّد مجاني | وحدة فئة 1 / 2 / 3 على الاحتياط (من المخزون المشترك، وتفضّل عالم البطل) |
| كنز | +6 / +8 / +10 ذهب |
| تدريب مكثّف | +6 / +8 / +10 خبرة |
| جوهر نقي | +3 / +3 / +4 جوهر |
| غنيمة | معدة عشوائية |
| بركة الغضب / الحجر / الريح | الفريق كله +8–12% هجوم / +10–15% صحة / +8–12% سرعة، **دائمة** لبقية المباراة |
| ماء الحياة | +10 / +12 / +15 حياة للبطل (حتى الحد الأقصى) |

المجموعات المتاحة تختلف حسب المرحلة (`REWARD_POOLS` في `data.js`): المرحلة 1 اقتصادية، 2 معدات وبركات، 3 بركات وشفاء.

---|---|
| **الغضب** داخل القتال: الضرر يتصاعد بعد 18 ث | +12% لكل ثانية |
| حد زمني للقتال ⇒ تعادل | 30 ث |
| **انهيار الصدع**: من الجولة 8 يخسر البطلان حياة إضافية كل جولة (لو سقطا معًا يفوز من فاز بالجولة) | 3، 6، 10، 15، 21، 28… |
| حد أقصى للجولات (الأعلى حياة يفوز) | 18 |

نتيجة المحاكاة الحالية: متوسط **8.8 جولات**، 98% من المباريات تنتهي بين 7 و11 جولة ⇒ تقريبًا **5–7 دقائق** للاعب بشري.

## 3. آلية القتال

### الإحداثيات
```
 y=5   مركز قيادة الخصم (بطله إن لم يُستدعَ)
 y=4   صف الخصم الخلفي      ┐
 y=3   صف الخصم الأمامي      ┘ 4 أعمدة × صفان
 ───── خط الصدع (y=2)
 y=1   صفك الأمامي  = خط الدفاع
 y=0   صفك الخلفي
 y=-1  مركز قيادتك
```
الحركة مستمرة (ليست خانات)، والمحاكاة بخطوات 0.05 ث، حتمية بالكامل لبذرة معينة.

### دورة كل وحدة
1. تحديث التأثيرات (التعزيزات، الحرق، الشلل، التجدد).
2. اختيار هدف: **الأقرب** القابل للاستهداف؛ الاستفزاز (taunt) يفرض الهدف؛ **القتلة** يفضلون البطل المكشوف ثم الصف الخلفي.
3. إذا امتلأت المانا ⇒ تُطلق المهارة الخاصة.
4. إذا كان الهدف خارج المدى ⇒ تتحرك نحوه، وإلا تهاجم بحسب سرعة الهجوم.

المانا: +10 لكل هجمة، +3 لكل ضربة تتلقاها. الضرر = الهجوم × (1 − الدفاع) × الغضب × (حرجة؟). المهارات تتجاهل نصف الدفاع.

### اختراق الدفاع
- **القتلة** يقفزون عند 0.6 ث خلف الصف الخلفي للعدو.
- **القناصة** بمدى 4 يصلون للصف الخلفي من البداية؛ مهارة "تصويب دقيق" تقنص الأقل صحة أينما كان.
- مهارات المنطقة تصيب كل من في نصف القطر.

### نظام حماية البطل والخسارة
| الحالة | قابل للاستهداف؟ |
|---|---|
| البطل في مركز القيادة وخط الدفاع (أي وحدة حية في الصف الأمامي) قائم | ❌ |
| سقط كل الصف الأمامي (أو لم تضع أحدًا فيه) | ✅ "مكشوف" |
| البطل مستدعى في الصف الخلفي وخط الدفاع قائم | ❌ لكن **ضرر المنطقة يصيبه** |
| البطل مستدعى في الصف الأمامي | ✅ دائمًا (هو خط الدفاع) |

- عند فناء جميع وحدات جانب ⇒ **هجوم على مركز القيادة** لمدة 4 ث من الناجين.
- مركز القيادة **محصّن**: يتلقى 25% فقط من الضرر، و**بحد أقصى** `3 + 0.5×الجولة` حياة لكل قتال.
- **وصول حياة البطل للصفر ⇒ خسارة فورية للمباراة** (في أي لحظة، حتى وسط القتال).

### استدعاء البطل (مخاطرة ومكسب)
| المكسب | المخاطرة |
|---|---|
| يقاتل بنفسه (هجوم 75–85 + 5 لكل جولة، صحة = الحياة × 10) | يتلقى الضرر **كاملًا** (لا تحصين) |
| +5% هجوم لكل الحلفاء | ضرر المنطقة يصيبه حتى وهو محمي |
| قدراته أرخص بـ 1 جوهر | بعد خسارة 12 حياة في قتال واحد **ينسحب** لمركز القيادة |
| | إذا كانت حياته منخفضة قد يموت في الساحة ⇒ خسارة فورية |

المحاكاة: من استدعى بطله مرة على الأقل فاز في 56.8% من المباريات. الاستدعاء مفيد لكنه ليس مضمونًا، وهذا هو المطلوب.

### ضرر البطل عند خسارة الجولة
`ضرر مباشر (من الضربات)` + `ارتداد الخسارة = 2 + الجولة×0.35 + نجوم وحدات الخصم الناجية (بحد أقصى 6)` + `انهيار الصدع (من الجولة 10)`.
التعادل: `2 + الجولة/3` لكل بطل.

### قدرات البطل
لكل بطل قدرة سلبية وقدرتان نشطتان تستهلكان **الجوهر**. يختار اللاعب لكل قدرة **متى تتفعّل**:
بداية القتال / بعد 5 ث / عند سقوط أول حليف / عند انكشاف البطل.
الجوهر يُحجز عند التجهيز ويُدفع **فقط إذا تفعّلت** القدرة (وإلا يُسترد).

## 4. البطاقات والشخصيات

**20 وحدة** في 4 عوالم و6 أدوار، بثلاث فئات تكلفة (8 × فئة 1، 7 × فئة 2، 5 × فئة 3)، بالإضافة إلى **6 معدات** و**4 تعاويذ**.

القيم الأساسية للدور (فئة 1، نجمة واحدة)، والفئة تضرب الصحة والهجوم (×1 / ×1.22 / ×1.5):

| الدور | الصحة | الهجوم | سرعة | المدى | الدفاع | حرجة | نقطة القوة | نقطة الضعف |
|---|---|---|---|---|---|---|---|---|
| حارس | 620 | 44 | 0.6 | 1 | 25% | 5% | تحمّل، استفزاز | ضرر منخفض |
| مقاتل | 540 | 60 | 0.75 | 1 | 12% | 5% | متوازن | لا يخترق |
| قاتل | 420 | 68 | 0.85 | 1 | 5% | 25% | يقفز للخلف | هش |
| ساحر | 420 | 38 | 0.6 | 3 | 0 | 5% | مهارات منطقة | هش، بطيء البداية |
| قناص | 370 | 60 | 0.75 | 4 | 0 | 10% | ضرر مستمر بعيد | الأهش |
| دعم | 450 | 32 | 0.6 | 3 | 5% | 5% | علاج/تسريع | ضرر ضئيل |

لا توجد وحدة تتفوق في كل الخصائص: كل دور يدفع ثمن قوته. كل عالم **ينقصه دور واحد على الأقل**، فيحتاج اللاعب للخلط:
الجمر بلا دعم، المدّ بلا قاتل/قناص، نيون بلا ساحر، الغابة بلا دعم.

**المهارات** تُعرَّف بيانيًا (`type` + قيم لكل نجمة): `nuke, cleave, aoe, stunAoe, stunStrike, burn, drain, execute, snipe, multishot, taunt, shieldSelf, healSelf, healLowest, healAll, hasteAllies`. إضافة وحدة جديدة = إدخال بيانات فقط.

## 7. التطوير

- 3 نسخ متطابقة بنفس النجوم ⇒ دمج تلقائي في نجمة أعلى (الحد ★★★). يحتفظ بموقعه في الساحة، وتنتقل المعدات معه (والزائد يعود للحقيبة).
- الشراء مسموح حتى لو امتلأ الاحتياط **إذا** كان سيؤدي لدمج فوري.
- الصحة والهجوم: ★ ×1 ، ★★ ×1.8 ، ★★★ ×3.0. قيم المهارات لها جدول خاص لكل نجمة.
- **منع الوحدة التي لا تُهزم:** السرعة والمدى والدفاع **لا** تتغير بالنجوم؛ والحد ★★★؛ والمخزون المشترك يجعل الوصول لثلاث نجوم مكلفًا (9 نسخ)؛ والاستفزاز والشلل يضبطان الحاملين الأقوياء.
- شاشة التطوير تعرض لكل وحدة: النسخ عند كل مستوى، التقدم نحو النجمة التالية، معاينة التغيير (صحة/هجوم/مهارة)، المخزون المتبقي، وزر شراء إن كانت في المتجر.

## 8. نظام البيانات

### كائنات المباراة (`core/match.js`)
```js
Player = {
  heroId, life, maxLife, gold, xp, level, essence,
  bench: [Unit|null ×6],
  board: { 'f0'..'f3', 'b0'..'b3' → Unit },   // f = أمامي، b = خلفي
  items: [itemId], armedSpells: [itemId],
  abilities: { abilityId → trigger },
  summoned, heroSlot, shop: [unitId ×5], itemShop: [itemId ×2], shopLocked,
  winStreak, lossStreak, stats: {...}
}
Unit = { uid, defId, star, items: [itemId] }
Match.pool = { unitId → النسخ المتبقية }       // مشترك
Match.history = [ تقرير كل جولة ]              // للإحصائيات وإعادة العرض
```

### واجهة Match (يستخدمها البشر والذكاء الاصطناعي والمحاكي)
`startRound · buy · sell · reroll · buyXp · toggleLock · move · buyItem · equip · unequip · armSpell · setAbility · toggleSummon · moveHero · autoFill · createCombat · resolveCombat`

كل عملية تعيد `{ ok, reason }`؛ والواجهة لا تحتوي أي قاعدة لعب.

### القتال
`new Combat([specA, specB], { seed, round })` ثم `step()` أو `runToEnd()` ⇒
`{ winner, duration, sides: [{ heroLife, heroKilled, survivors, abilitiesFired, exposed }], unitDamage }`.
الأحداث (`damage, heal, cast, attack, death, exposed, assault, retreat, heroAbility, spell, …`) تُستخدم للعرض فقط.

### بيانات التوازن (`core/telemetry.js`)
تُحفظ في `localStorage` وتُصدَّر JSON من شاشة الإحصائيات: نسب فوز الأبطال، استخدام كل وحدة ونسبة فوزها، وظهورها في التشكيلة النهائية، وعدد مرات ★★★، وتفعيل التآزر، ونجاح الاستدعاء، ومتوسط الجولات والمدة.

```
node tools/simulate.js 1000     # تقرير توازن من 1000 مباراة ذكاء اصطناعي
node tools/test.js              # اختبارات القواعد
```

## 10. قرارات مفتوحة (قيم افتراضية حتى الآن)
- هل يُحتسب البطل المستدعى ضمن حد الوحدات؟ حاليًا **لا**: إنه جسد إضافي مقابل المخاطرة.
- حد ضرر مركز القيادة ومدة الهجوم عليه (`postDamageCap*`, `assaultWindow`).
- عتبة انسحاب البطل المستدعى (`summonKnockout = 15`).
- عدد الأبطال (4) والوحدات (20) مقصود صغيرًا للنموذج الأولي.
- اللعب عبر الشبكة: الخادم يملك `Match`، والعميل يرسل الأوامر فقط، ويُعاد تشغيل القتال من البذرة للتحقق.
